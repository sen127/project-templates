# Project Templates

Reusable, company-neutral templates for product, software, data, and delivery work.

## Available templates

- [`HLRD-Template.md`](HLRD-Template.md) - concise High-Level Requirements Document template for defining business context, scope, functional requirements, non-functional requirements, operational needs, risks, and traceability.
- [`RTM-Template.xlsx`](RTM-Template.xlsx) - lightweight Requirements Traceability Matrix for controlling scope and product drift during delivery. Reuse the exact objective and requirement IDs from the HLRD rather than creating a second requirements set.

## Placeholder convention

Replace values in square brackets, for example `[Company Name]`, `[Project Name]`, `[Version]`, `[Owner]`, and `[Date]`, when adapting a template to a specific initiative.

## Usage principle

Keep each template at the level needed for alignment and decision-making. Link to detailed designs, user stories, test cases, architecture documents, or operating procedures instead of duplicating them here.

The HLRD is the agreed baseline. The RTM is the lightweight delivery control sheet. Update the HLRD only for genuine baseline or scope changes; update the RTM as requirements move through delivery and validation.
